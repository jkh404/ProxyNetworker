# UDP 网状路由

本文说明 ProxyNetworker UDP 虚拟网络的候选发现、链路测量、最短路径选择、多跳转发和故障回退机制。QUIC 当前仍使用服务端可靠中继，不在这套 P2P mesh 数据面内。

## 目标

两个虚拟网络节点通信时，不应固定绕行服务端。节点需要根据当前网络状态选择成本最低的可用路径：

```text
A 直接到 B
A -> C -> B
A -> 服务端中继 -> B
```

路径选择考虑 RTT、抖动、丢包率和跳数。服务端中继作为网格路径不可用时的最终兜底。

## 控制面

### 候选地址

客户端启动后向服务端发送 `PeerCandidates` 帧，内容包括：

- 客户端本地 IPv4 候选地址。
- 服务端观察到的公网 IPv4 端点。
- 可选的手动附加候选地址。

每个候选列表最多编码 16 个端点。服务端在节点上线、心跳和新候选到达时，将候选地址广播给同一虚拟网络中的其他节点。

### 链路测量

节点通过加密 `PathProbe` 和 `PathProbeAck` 测量每个候选链路，并维护：

- EWMA RTT，当前采样权重为 20%。
- RTT 抖动。
- 探测发送数和成功响应数计算出的丢包率。
- 最近成功时间和最近探测时间。

累计探测计数超过 256 后会减半，避免旧网络状态永久影响链路评分。单个候选地址不可达时只记录该路径失败，不会中断其他候选探测或心跳。

### 链路状态通告

节点通过心跳周期向服务端发送 `MeshLinkState` 帧。通告包含该节点当前可用的直连邻居及对应 RTT、抖动和丢包率。单个通告最多包含 64 条直连链路。

服务端验证来源节点后，将通告广播给其他在线节点。通告带有单调递增序号，节点只接受比本地记录更新的版本。

## 路径成本

每条有向链路的成本为：

```text
cost = RTT + (jitter * 2) + (loss_basis_points / 50) + 2 ms
```

其中：

- RTT 和抖动单位均为毫秒。
- 丢包率使用 `0..10000` 的 basis points 表示。
- 丢包惩罚最高约为 200 ms。
- `2 ms` 作为每条链路的基础跳数成本。
- 单条链路成本限制在 `1..120000 ms`。

节点使用 Dijkstra 算法计算从自身到其他节点的最低成本有向路径。路径最大为 8 跳。

## 数据面

单播数据使用 `MeshPacket` 帧封装：

- 原始 IPv4 目标地址。
- 当前 Hop Count。
- Hop Limit。
- 原始 IP 数据包。

节点按照路由表选择下一跳。若下一跳是目标节点，则直接投递到 TUN；若下一跳是中间节点，则重新封装并转发。Hop Count 会随节点转发递增，达到限制后数据包被丢弃，以防止路由环路。

服务端中继参与成本比较。若网格路径缺失或不再健康，客户端将 `MeshPacket` 发送到服务端，由服务端投递到目标节点。网格路径与中继路径使用 3 ms 滞回阈值，减少频繁切换。

当前日志和 `run.sh status` 可显示：

```text
Path: direct 10.66.0.2 -> 10.66.0.3:41001 (1.2 ms; route 10.66.0.2 -> 10.66.0.3)
Path: mesh 10.66.0.2 -> 10.66.0.3 -> 10.66.0.4 (6.0 ms; route 10.66.0.2 -> 10.66.0.3 -> 10.66.0.4)
Path: relay 10.66.0.2 -> 10.66.0.4 (2.1 ms)
```

## 故障处理

- 候选探测失败按单个端点隔离，不终止整个心跳循环。
- 单节点探测出现 socket 错误时，该节点的直连路径进入默认 30 秒冷却期；共享 UDP socket 收到连接重置时暂停全部直连并回退中继。
- relay-only 客户端发送 `RelayRequired`，服务端停止向其他节点广播它的直连候选，避免别人继续向它发起不可用连接。
- 超过 `PeerTimeout` 未成功的直连路径不再参与路由。
- 链路状态超过两倍 `PeerTimeout` 未更新时从路由图中移除。
- 节点封禁由服务端拒绝注册、候选广播和 Mesh 数据帧转发。
- 中间路线失效后，下一条数据包会重新选择可用 mesh 路径或服务端中继。

## 安全边界

虚拟网络帧使用该网络的 256 位会话密钥进行 AES-GCM 加密和完整性校验。Token 只用于获取网络配置和会话密钥。

当前设计下，同一虚拟网络中的所有节点共享会话密钥。多跳中间节点转发数据时需要解密 `MeshPacket`，因此能读取经过它的业务 IP 包。这与现有“同网络节点互相信任”模型一致，但不提供对中间节点的端到端隐私保护。

后续若需要更强隐私边界，应增加：

- 不暴露业务载荷的外层路由头。
- 节点间密钥协商。
- 端到端业务加密与逐跳传输加密分离。

## QUIC 现状

QUIC 当前提供加密可靠流和服务端中继，不提供 P2P mesh。主要限制是 .NET 高层 QUIC API 不能让 `QuicListener` 与出站 `QuicConnection` 共享同一个 UDP 端口，因此无法直接复用服务端观察到的 NAT 映射完成 ICE 式打洞。

真正的 QUIC P2P mesh 需要继续实现：

- 原生 MsQuic socket/UDP binding 控制。
- ICE/STUN 候选与连通性检查。
- NAT 映射保活和失败回退。
- QUIC 链路 RTT、丢包和路径切换。

## 测试覆盖

自动化测试位于 `ProxyNetworker.Core.Tests`：

- 多跳路径优先和更优直连切换。
- 链路状态编解码。
- Mesh Packet Hop Limit。
- 三节点 `A -> C -> B` UDP 端到端数据转发。
- relay-only 节点不会被广播为直连候选，其他节点实际选择服务端中继。

本地已通过 Release 构建、5 个自动测试、Windows x64 Native AOT 发布和 Linux x64 服务端发布。真实公网 `Windows -> Ubuntu -> Raspberry Pi` 多跳测试仍应在部署候选版本后单独执行。
